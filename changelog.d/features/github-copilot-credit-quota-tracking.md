- **feat(providers):** GitHub Copilot (including GitHub Enterprise / `ghe-copilot`) AI-credit usage now appears in **Usage → Provider Limits** with credits used / entitlement, remaining percentage and reset date. Copilot stamps every inference response with `x-quota-snapshot-*` headers (`crUsed`/`ent`/`totRem`/`rem`/`rst`/`ov`/`ovPerm`); those are captured passively on the chat path (streaming and non-streaming, URL-decoded, `ent=-1` treated as unlimited, overage retained) and stored through the existing quota cache + quota-snapshot persistence — no new table, no extra chat request. `ghe-copilot`, which has no reachable `copilot_internal/user` endpoint on a data-residency tenant, is now a first-class provider-limits entry and falls back to the captured snapshot instead of showing nothing. A window with `ovPerm=true` is informational for routing: once the included credits are consumed the account keeps serving on paid overage, so the capture can never park the connection until the monthly reset (and the dashboard marks the row `overage`); `ovPerm=false` still marks the connection exhausted until reset, since upstream has no way to serve a credit-billed request then.
