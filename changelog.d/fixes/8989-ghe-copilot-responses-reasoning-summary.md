- **fix(executors):** GitHub Copilot / GHE Copilot `/responses` requests now inject `reasoning.summary` when an effort is set and no explicit summary was requested, so clients see visible reasoning text instead of encrypted-only blocks. Measured live against a deployed GHE Copilot `/responses` endpoint (gpt-5.6-luna) via `response.reasoning_summary_text.delta` events: `"concise"` yields ~5.3k chars of visible summary text, `"detailed"` ~34.8k (≈6.6× more). The reasoning items themselves still carry `encrypted_content` (upstream design, bound to the item/organization and never recoverable by a proxy); the visible text is the separately-streamed summary deltas. The injected value defaults to `"concise"` and can be changed per deployment via the `OMNIROUTE_RESPONSES_REASONING_SUMMARY` env var (`concise` | `auto` | `detailed`); invalid values fall back to the default instead of being forwarded (the upstream rejects bogus values with HTTP 400 `unsupported_value`). Covers both the `reasoning` object form and top-level `reasoning_effort` (OpenAI-shaped bodies), and is client-wins (an explicit client summary is never overridden).
